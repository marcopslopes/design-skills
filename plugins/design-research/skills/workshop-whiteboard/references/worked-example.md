## Board output (excerpt)

```markdown
## Workshop whiteboard — Recurring appointments adoption

**Problem (reframed):** Understand how providers currently rebook repeat
services and what blocks them from setting a recurring pattern — not
"how do we push the feature."

**Business impact / KPIs:** Recurring booking rate, time-to-rebook,
support tickets about "book again."

**Goals (≤3):**
1. Discover current rebooking process and workarounds
2. Learn barriers to committing to a recurring schedule
3. Evaluate whether the current recurring UI matches those mental models

**Methods + why:** 8 generative interviews (behavior: rebooked same
service 2+ times in 3 months) + 5 UT sessions on the existing recurring
flow — interviews for barriers, UT for whether the UI matches.

**Recruitment:** Behavior-first screener (see screener-builder) · remote

**Sample Qs:** "Walk me through the last time you booked the same
service again…" / UT: reschedule without using the word "recurring"

**Timeline:** ~3 weeks · if only 1 week: UT-only on live flow + prior
findings sweep

**Handoff:** decision-first-research Decision Brief → screener-builder →
usability-test-guide
```
