# Lenses to invite

Pick a **subset** that matches the stage. Do not invite the full
checklist every time. Name sources when a company ritual exists; do not
invent house lenses.

## Load order

1. A pasted "How we critique" / UX-review Confluence (or wiki) URL —
   use that page's lenses and frame questions.
2. Else a `COMPANY-SOURCES.md` row that names the critique / UX-review
   ritual (org-pack resolution, `harness/ORCHESTRATOR.md` §0a).
3. Else the generic set below. Say so in one line
   (`Lenses: generic — no company critique ritual loaded`).

## Generic fallback (five)

| Lens | Invite when |
|------|-------------|
| **Usability** | Can someone finish the job in this moment? |
| **Information architecture** | Are the places and labels right? |
| **Content** | Do the words carry the decision? |
| **Visual hierarchy** | Does the eye land where the action is? |
| **Feasibility / scope** | Is this buildable in the named slice? |

## Stage match

| Stage | Lean toward | Soft-pedal |
|-------|-------------|------------|
| Early concept | Direction, problem framing, what's off the table | Pixel polish, final copy |
| Mid-fi | Flow, IA, the feedback ask they named | Brand-new problem statements |
| Final check | One named area, edge cases, capture of decisions | Reopening the concept |

If the loaded company ritual has its own stage language, prefer that.
Never mix a missing local org-pack file with the public example pack
(§0a — flag the gap instead).
